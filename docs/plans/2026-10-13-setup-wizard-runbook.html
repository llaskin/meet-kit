Already proven by the automated suite (505/505, not repeated here): validators and wrangler-output parsers; wrangler.jsonc edits keep every comment; secrets go to wrangler secret put on stdin and are never in argv, responses or the state file; steps refuse to run out of order; the test-failure gate stops a deploy; any admin path answering 200 is a hard stop; a /meet locked by Access fails the check; the local server enforces its token, Host and Origin checks and runs one action at a time. Seven of these gates were mutation-tested (each broken on purpose → its test failed). The leak-check test no longer blocks the deploy once your own email and name are filled in (simulated with a work-domain email and a surname; the untouched template is still checked). The page was rendered and inspected at 820px and 500px. The deploy bundle contains no wizard code.

⚠️ RULES — read before 1a

  • Use a Cloudflare account that does not already run meet-kit. The wizard deploys a Worker named meet-kit and reuses any D1 database named meet-kit. On your own account that would overwrite your live booking page and point it at your real bookings.
  • Run it from the fresh clone made in 0a, never from your working repo: the wizard edits wrangler.jsonc and meet.config.json.
  • Never paste a secret into Claude Code. Secrets go only into the wizard page.
  • If any admin page (/admin/, /api/admin/…) ever loads without the Access login, stop and report it.

Rollback = section 7: delete the test Worker, D1 database, Turnstile widget, Access application and Google Cloud project. Nothing on main changes until 8b.
